# Руководство по облачному развёртыванию

Проект подготовлен к публикации на облачной платформе Render (или аналогичном Linux-хостинге) с использованием связки Gunicorn + WhiteNoise + PostgreSQL.

## 1. Подготовка базы данных (PostgreSQL)
Локальная база данных SQLite (`db.sqlite3`) и облачная PostgreSQL не являются одной и той же базой. Данные из локальной разработки не переносятся автоматически, облачная БД создаётся пустой.
1. Перейдите на сайт *render.com* и зарегистрируйтесь (если ещё не зарегистрированы), например, с помощью *GitHub*.
2. В панели Render создайте новый сервис **PostgreSQL** (New Postgres).
3. Задайте имя (например, `dealership-db`) и выберите бесплатный тариф (Free).
4. Дождитесь статуса **Available** и скопируйте значение **Internal Database URL**.
*Примечание: Internal Database URL используется для безопасного и быстрого соединения внутри внутренней сети платформы Render. Публиковать фактическое значение этого адреса строго запрещено.*

## 2. Настройка веб-сервиса (Web Service)
1. Создайте новый **Web Service** и подключите GitHub-репозиторий с проектом.
2. Укажите следующие параметры сборки и запуска:
   * **Language:** Python 3
   * **Build Command:** `bash build.sh` (устанавливает зависимости из `requirements.txt` и собирает статику)
   * **Start Command:** `gunicorn config.wsgi:application --bind 0.0.0.0:$PORT` (запускает WSGI-сервер)

## 3. Переменные окружения (Environment Variables)
Во вкладке Environment настройте параметры конфигурации. Безопасные примеры представлены ниже, реальные секреты в код не коммитятся:
* `DATABASE_URL` = [вставьте скопированный Internal Database URL]
* `DJANGO_SECRET_KEY` = [сгенерируйте длинную случайную строку]
* `DJANGO_DEBUG` = `False`
* `DJANGO_ALLOWED_HOSTS` = `your-dealership.onrender.com` (без https://)
* `DJANGO_CSRF_TRUSTED_ORIGINS` = `https://your-dealership.onrender.com` (с https://)

## 4. Инициализация и миграции
После успешного деплоя (статус Live) база данных пуста. 
1. Откройте встроенный терминал (Shell) в панели Web Service.
2. Выполните команду применения структуры БД:
   ```bash
   python manage.py migrate
Поскольку на бесплатном тарифе платформы Render недоступен встроенный терминал (Shell), миграции удалённой базы данных PostgreSQL выполняются через добавление команды в сценарий сборки:
1. В корне проекта откройте файл `build.sh` и временно добавьте третьей строкой: `python manage.py migrate`[cite: 2].
2. Сделайте коммит и отправьте код в репозиторий (`git push`).
3. Render автоматически запустит деплой, применит миграции к PostgreSQL и создаст все необходимые таблицы.
4. (Опционально) Для создания профиля администратора без использования Shell подключитесь к базе через локальный терминал, используя скопированный `External Database URL` (`$env:DATABASE_URL="External Database URL"`), и выполните команду `python manage.py createsuperuser`.
