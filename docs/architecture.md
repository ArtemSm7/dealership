# Архитектура и структура проекта

## Структура каталогов
Проект имеет модульную структуру на базе фреймворка Django:
*   `config/` — главная конфигурация проекта (маршруты `urls.py`, настройки `settings.py`, точка входа WSGI).
*   `main/` — основное приложение автосалона (модели, сериализаторы, контроллеры DRF).
*   `templates/` — HTML-шаблоны пользовательского интерфейса (SPA и базовые компоненты Tabler).
*   `static/` — локальные статические файлы. Включает подкаталог `main/`, внутри которого расположены файлы UI-фреймворка: `css/tabler.min.css` и `js/tabler.min.js`.
*   `staticfiles/` — каталог для собранной статики (генерируется автоматически при деплое).
*   `docs/` — комплект технической документации.
*   `build.sh` — bash-скрипт для автоматической сборки проекта на сервере.
*   `requirements.txt` — зафиксированный список Python-зависимостей.
*   `.env.example` — безопасный шаблон переменных окружения.

## Архитектурная схема
Взаимодействие компонентов в эксплуатационном режиме (Production) организовано следующим образом:

[ Клиент (Браузер) ] 
       │ (HTTPS / Fetch API)
       ▼
[ Облачный веб-сервис Render ] 
       │ (HTTP)
       ▼
[ WSGI-сервер Gunicorn ] ─── [ Django REST Framework ]
       │                             │
       ▼                             ▼
[ WhiteNoise Middleware ]    [ СУБД PostgreSQL ]
 (Обслуживание статики)     (Персистентное хранение)

*   **Клиентская часть:** SPA-интерфейс, отправляющий асинхронные запросы без перезагрузки страниц.
*   **Серверная часть:** Gunicorn обрабатывает запросы и передает их в Django.
*   **Статика:** WhiteNoise перехватывает запросы к статическим файлам и отдает их со сжатием и кэшированием.
*   **СУБД:** PostgreSQL на платформе Render обеспечивает надежное хранение данных, независимое от перезапусков веб-сервиса.
